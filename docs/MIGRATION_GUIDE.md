# AES CareOffice — Migration & Deployment Documentation

This guide documents the migrated **Vite + React + TypeScript + Supabase + Vercel** architecture, local development setup, database migration workflow from InfinityFree/MySQL, Row Level Security (RLS) model, and exact step-by-step instructions to provision **Supabase** and **Vercel** when you are ready.

> **Original PHP Project Preserved**: All original PHP, SQL, and InfinityFree deployment files in the repository root remain untouched so your live site continues working until final cutover.

### Key Architectural Improvements Over PHP/InfinityFree
1. **Authentication & Security**: Replaced the hardcoded `'password123'` login bypass and PHP session cookies with **Supabase Auth** JWT sessions (`supabase.auth.signInWithPassword`, password change re-authentication, and functional email password recovery at `/reset-password`).
2. **Row Level Security (RLS)**: Every table enforces RLS using `public.is_admin()`, allowing access only to verified accounts listed in `public.admins`. Public/anonymous access is completely revoked.
3. **Atomic Multi-Table Transactions**: Multi-table operations (`create_learner_with_parents`, `update_learner_with_parents`, `create_parents_for_student`, `create_case_with_students`, `update_case_with_students`) execute inside PL/pgSQL RPC functions (`BEGIN ... COMMIT/ROLLBACK` semantics), preserving full transactional integrity.
4. **Serverless-Compatible Sections Storage**: `config/sections.json` file writes (which fail on Vercel's read-only filesystem) are replaced by the `public.grade_sections` PostgreSQL table and `public.add_grade_section()` RPC.
5. **Lazy-Loaded Vector PDF Export**: `jspdf` + `jspdf-autotable` are dynamically imported on Export click so the initial app bundle stays fast.

## 2. Database Schema & MySQL-to-PostgreSQL Differences

| MySQL Table (`assets/sql/database.sql`) | PostgreSQL Table | Key Conversion Notes |
| :--- | :--- | :--- |
| `admins` | `public.admins` | `password` column omitted (handled by `auth.users`); `auth_user_id UUID` links Supabase Auth user to admin allowlist. |
| `students` | `public.students` | `INT AUTO_INCREMENT` -> `BIGINT GENERATED BY DEFAULT AS IDENTITY`; `TIMESTAMP` -> `TIMESTAMPTZ`; indexes on `deleted_at`, `(grade_level, section, status)`, `lrn`. |
| `parents` | `public.parents` | `ENUM('Primary','Secondary')` -> `public.parent_type_enum`; FK `student_id` preserves `ON DELETE CASCADE`. |
| `assessment_records` | `public.assessment_records` | Preserves `UNIQUE` constraint on `record_number` and FK `student_id`. |
| `case_register` | `public.case_register` | Preserves `UNIQUE` constraint on `case_number`; view `public.case_register_view` replaces MySQL `GROUP_CONCAT` using PostgreSQL `STRING_AGG` and `ARRAY_AGG`. |
| `case_students` | `public.case_students` | Preserves composite PK `(case_id, student_id)` and cascading FKs. |
| *(config/sections.json)* | `public.grade_sections` | Case-insensitive unique index `(grade_level, lower(section_name))`. |
| `cars_assessment_sessions`, `cars_student_evaluations`, `cars_norm_tables` | Preserved in `public` | `tinyint(1)` mapped to `SMALLINT`; MySQL `ENUM`s converted to PG enums; `ON UPDATE CURRENT_TIMESTAMP` migrated to `set_updated_at()` triggers. |

## 4. What to Do in Supabase (Step-by-Step)

When you are ready to create your Supabase project, follow these exact steps:

### Step 4.1 — Create the Project & Get API Keys
1. Sign in to [Supabase](https://supabase.com) and click **New Project**.
2. Choose an organization, enter a project name (e.g., `aes-careoffice`), set a strong database password (save it securely), select the region closest to your school, and click **Create new project**.
3. Wait ~1–2 minutes for provisioning, then go to **Project Settings → API** (or **Data API / API Keys**):
   - Copy **Project URL** → `VITE_SUPABASE_URL`
   - Copy **anon / public key** → `VITE_SUPABASE_ANON_KEY`
   - **NEVER** copy or use the `service_role` key in `frontend/` or Vercel `VITE_*` variables.

### Step 4.2 — Run the Database Schema, Functions, RLS, and Seed SQL
1. In the Supabase Dashboard, open **SQL Editor → New Query**.
2. Execute the migration files **in exact order**:
   1. Paste and run [`supabase/migrations/001_initial_schema.sql`](../supabase/migrations/001_initial_schema.sql)
   2. Paste and run [`supabase/migrations/002_functions_and_rpcs.sql`](../supabase/migrations/002_functions_and_rpcs.sql)
   3. Paste and run [`supabase/migrations/003_rls_policies.sql`](../supabase/migrations/003_rls_policies.sql)
   4. Paste and run [`supabase/migrations/004_seed_sections.sql`](../supabase/migrations/004_seed_sections.sql)

### Step 4.3 — Migrate Your Existing MySQL Records (If Keeping InfinityFree Data)
1. Open **phpMyAdmin** from InfinityFree (or local XAMPP) → select your `aes` database → click **Export**.
2. Choose **Custom**, format **SQL**, and ensure **Data** (all `INSERT INTO` rows) is included. Download e.g. `aes_export.sql`. *(Your original MySQL database is never modified).*
3. On your local machine (from repository root), convert the MySQL export to PostgreSQL SQL:
   ```powershell
   node supabase/scripts/convert_mysql_dump.mjs path\to\aes_export.sql supabase\005_data_import.sql
   ```
4. Inspect `supabase/005_data_import.sql` (notice legacy `admins` passwords are safely stripped while emails are preserved).
5. Paste and run `supabase/005_data_import.sql` in **Supabase SQL Editor**.
6. Compare the printed verification `row_count` output against your MySQL table counts to confirm 100% record parity. *(Do not commit `005_data_import.sql` to public GitHub if it contains sensitive student/parent records!)*

### Step 4.4 — Configure Supabase Auth & Create Counselor Accounts
1. Go to **Authentication → Providers → Email**:
   - Disable **Allow new users to sign up** (recommended: turn **OFF** public self-registration under **Authentication → Sign In / Providers** or **User Signups** so only counselors you invite/create can log in).
2. Go to **Authentication → URL Configuration**:
   - Set **Site URL** to your Vercel production URL (e.g., `https://aes-careoffice.vercel.app`).
   - Add **Redirect URLs**: `http://localhost:5173/reset-password` and `https://aes-careoffice.vercel.app/reset-password`.
3. Create counselor account(s) in **Authentication → Users → Add user → Create new user**:
   - Enter the counselor's email and a strong initial password (check **Auto Confirm User**).
4. Ensure each counselor's email exists in `public.admins` (if starting fresh without a MySQL import, run in SQL Editor):
   ```sql
   INSERT INTO public.admins (email)
   VALUES ('counselor@yourschool.edu')
   ON CONFLICT (email) DO NOTHING;
   ```
   *(The `trg_link_auth_user_admin` trigger and `public.is_admin()` automatically authorize matching confirmed users.)*

### Step 4.5 — Test Locally Against Live Supabase
1. Copy `frontend/.env.example` to `frontend/.env.local` and fill in `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY`.
2. Run `cd frontend && npm run dev` and test login, Learners, Parents, Assessments, Cases, Graduates, Archive, Password Change, and Forgot Password.

## 5. What to Do in Vercel & GitHub (Step-by-Step)

### Step 5.1 — Push Your Code to GitHub
1. Verify `frontend/.env.local` and any sensitive `.sql` data dumps are NOT staged (`git status`).
2. Commit the `frontend/` and `supabase/migrations/` folders and push to GitHub.
   *(Note: `.github/workflows/deploy.yml` currently FTP-deploys the root PHP site to InfinityFree on pushes to `main`. Keep or disable that workflow once you fully cut over from InfinityFree to Vercel.)*

### Step 5.2 — Deploy on Vercel
1. Sign in to [Vercel](https://vercel.com) with your GitHub account and click **Add New… → Project**.
2. Import your `AES_CAREOFFICE` repository.
3. Configure **Project Settings**:
   - **Framework Preset**: `Vite`
   - **Root Directory**: click **Edit** and select **`frontend`**
   - **Build Command**: `npm run build`
   - **Output Directory**: `dist`
4. Open **Environment Variables** and add:
   - `VITE_SUPABASE_URL` = your Supabase Project URL
   - `VITE_SUPABASE_ANON_KEY` = your Supabase anon public key
   - Scope: `Production`, `Preview`, and `Development`
5. Click **Deploy**.
6. Once deployed, copy the Vercel domain (e.g., `https://aes-careoffice.vercel.app`) and paste it into **Supabase → Authentication → URL Configuration → Site URL** and `.../reset-password` Redirect URLs.
7. Verify browser refreshes on nested routes (e.g. reload `/learners` or `/cases` directly) — `frontend/vercel.json` handles SPA fallback rewrites automatically.

## 6. Troubleshooting Guide

| Symptom | Cause | Resolution |
| :--- | :--- | :--- |
| **"Supabase Not Connected Yet" banner on `/login`** | Missing `VITE_SUPABASE_URL` or `VITE_SUPABASE_ANON_KEY`. | Create `frontend/.env.local` locally or add env vars in Vercel and redeploy. |
| **"Access Restricted" after signing in** | User exists in `auth.users` but email is missing from `public.admins` (or email unconfirmed). | Confirm user in Supabase Auth and `INSERT INTO public.admins (email) VALUES ('...');`. |
| **404 when refreshing `/learners` on Vercel** | Vercel Root Directory wasn't set to `frontend`, so `frontend/vercel.json` wasn't applied. | Set Root Directory to `frontend` in Vercel Project Settings and redeploy. |
| **Duplicate key error after importing MySQL rows** | Identity sequence wasn't synced after manual `INSERT`. | Re-run the `SELECT setval(...)` lines at the bottom of `005_data_import.sql`. |
| **Forgot Password link redirects to localhost in production** | Supabase **Site URL** still points to `http://localhost:3000`. | Update Site URL and Redirect URLs in Supabase → Authentication → URL Configuration. |
